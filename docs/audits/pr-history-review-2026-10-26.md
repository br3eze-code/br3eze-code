## Consolidation decisions

- **Single execution owner:** `src/core/agentRuntime.js` remains the intended canonical runtime. The hardware registry is mounted through it and the canonical `ToolRegistry`; the new training and knowledge systems remain separate libraries/adapters, not another agent loop.
- **Model training:** isolated `experiments/llm-js/**` includes scalar/tensor operations, Transformer/TinyGPT training, fine-tuning, checkpoints, repository corpus generation, and regression/smoke tests. A separate small numeric classifier is in `src/ml/**`; it is not represented as a conversational LLM.
- **Knowledge:** provenance-first ingestion, chunking, page-cited PDF text/table extraction, bounded Wikimedia import, allowlisted source connectors, lexical FTS5 and a small provider-neutral cosine-similarity adapter. Unreviewed material is not automatically approved for indexing/training.
- **Hardware:** a declared capability registry plus a read-only RouterOS adapter reusing the existing gateway manager. No generic shell execution or device-write operation is exposed. Live-router validation remains outstanding.
- **Repository hygiene:** current-tree removal of local settings, a local environment file, release keystore, and stale logs; hygiene gate and CI hooks added. This does not purge Git history, rotate credentials, or replace a signing key.
- **Runtime audit:** static runtime-construction/provider-boundary scan and architecture regression test added. Static matches are leads, not proof of live production reachability.
- **Dependencies:** closed dependency PRs are not replayed as a batch. Reconcile manifest, lockfile, compatibility, and current advisories before changing versions.
- **Known merge blockers:** the source PR #220 workflow reported 48 failing suites / 96 failing tests overall; the integration PR's fresh workflows are queued at the last check.
