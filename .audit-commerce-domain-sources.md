# Commerce and domain port audit

The master repository is `https://github.com/br3eze-code/br3eze-code` on the `upgrade/commerce-domains` branch, created from commit `8687d906` on `manus`.

The fetched sibling branches were:

- `agent/partner-platform-hardening`: `https://github.com/br3eze-code/br3eze-code/tree/agent/partner-platform-hardening`. It adds partner-platform services and payment-related architecture, but its `src/core/shop.js` has no useful delta against the master checkout implementation.
- `claude/debug-session-x31sgy`: `https://github.com/br3eze-code/br3eze-code/tree/claude/debug-session-x31sgy`. Its shop implementation is older and removes reviews, shipments, product URLs, and settled payment handling, so it is not being copied wholesale.
- `claude/www-mobile-design-iv2f5o`: `https://github.com/br3eze-code/br3eze-code/tree/claude/www-mobile-design-iv2f5o`. It contains the broad domain, printer, ask-engine, and payment file tree but does not provide a safe direct replacement for the current ESM master files.
- `https://github.com/br3eze-code/AgentOS`: the sibling AgentOS repository. Its `PaymentAgent.ts` and `PrinterAgent.ts` expose minimal MCP tools that persist payment/print jobs; they are reference patterns, not direct replacements for the master’s richer Firestore, payment-gateway, and PrintBroker implementations.

Port decisions: retain the master’s richer shop/order/review/shipment behavior; add dynamic payment discovery through the existing `PaymentGateway`; expose role-aware shop capabilities; add a passive all-domain menu catalog; and replace Telegram/WhatsApp network-only `/start` menus with domain-aware startup menus while preserving existing action fallbacks.
